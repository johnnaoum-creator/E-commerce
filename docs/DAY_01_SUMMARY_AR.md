# ملخص الشغل اليومي – مشروع Olist E-Commerce

**المرحلة:** Data Ingestion & Preparation  
**المهمة الحالية:** Initial Data Profiling  
**اليوم الأول**

## 1. تجهيز المشروع

بدأت بتجهيز بيئة العمل وتنظيم ملفات المشروع، وعملت الآتي:

- إنشاء فولدر المشروع وتنظيم الملفات.
- إنشاء بيئة افتراضية باستخدام Python Virtual Environment.
- تثبيت المكتبات المطلوبة، ومنها Pandas.
- وضع ملفات البيانات الأصلية داخل `data/raw`.
- إنشاء ملفات Python داخل `src` لفحص كل Dataset بشكل منفصل.

استخدمت بيانات Olist Brazilian E-Commerce Dataset، والبيانات عندي مكونة من 9 ملفات CSV.

## 2. فحص ملفات البيانات

بدأت أراجع كل ملف من حيث عدد الصفوف والأعمدة، وأسماء الأعمدة، والقيم الناقصة، والصفوف المكررة، وبعض قواعد صحة البيانات.

- عدد الصفوف: 99,441
- عدد الأعمدة: 5
- مفيش Missing Values.
- مفيش Duplicate Rows.
- مفيش تكرار في `customer_id`.
- عدد قيم `customer_unique_id` المختلفة: 96,096.

### ثانيًا: Orders

- عدد الصفوف: 99,441
- عدد الأعمدة: 8.
- اكتشفت قيم ناقصة في:
  - `order_approved_at`: عدد 160.

  - `order_delivered_customer_date`: عدد 2,965.
- مفيش Duplicate Rows أو تكرار في `order_id`.
- راجعت حالات الطلبات، ولاحظت إن فيه 8 طلبات حالتها Delivered لكن تاريخ التسليم للعميل ناقص.
- راجعت تواريخ الشراء والتسليم، وملقتش حالات تسليم قبل الشراء.
- لقيت 7,826 طلب اتسلم بعد التاريخ المتوقع للتسليم.

### ثالثًا: Order Items

- عدد الصفوف: 112,650.
- عدد الأعمدة: 7.

- راجعت الأسعار ومصاريف الشحن، وملقتش أسعار صفرية أو سالبة أو قيم شحن سالبة.

### رابعًا: Order Payments

- عدد الصفوف: 103,886.
- عدد الأعمدة: 5.
- مفيش Missing Values أو Duplicate Rows.
- راجعت المفتاح المركب `(order_id, payment_sequential)` وملقتش تكرار.

- اكتشفت 9 سجلات قيمة الدفع فيها صفر.

- فحصت السجلات دي بشكل منفصل عشان تتوثق للمراجعة قبل اتخاذ أي قرار بخصوصها.

### خامسًا: Order Reviews

- عدد الصفوف: 99,224.
- عدد الأعمدة: 7.
- فيه قيم ناقصة في:
  - `review_comment_title`: عدد 87,656.
  - `review_comment_message`: عدد 58,247.
- مفيش Duplicate Rows كاملة.
- درجات التقييم كلها داخل النطاق من 1 إلى 5.
- أثناء الفحص اكتشفت إن فيه 789 مجموعة من `review_id` المكررة، بإجمالي 1,603 صفوف مرتبطة بالمجموعات دي.
- راجعت المجموعات دي، ولقيت إن نفس `review_id` مرتبط بأكتر من `order_id`، مع تطابق بيانات التقييم والتعليق والتواريخ داخل كل مجموعة.
- كمان اكتشفت إن 547 طلب عنده أكتر من سجل Review.

## 3. التوثيق

بعد الفحص، جهزت ملفين داخل فولدر `docs`:

- `data_profiling.md`: فيه نتائج الفحص الأولي لكل ملف.
- `data_quality_report.md`: فيه ملخص لمشاكل جودة البيانات والملاحظات اللي محتاجة مراجعة.

وكمان قسمت عمليات الفحص على ملفات Python منفصلة داخل `src` عشان يكون سهل أرجع لكل Dataset وأراجع نتائجه.

## 4. حالة البيانات بعد الشغل

لحد دلوقتي اللي اتعمل هو فحص وتحليل أولي للبيانات وتوثيق الملاحظات فقط.

**مهم:** ملفات CSV الأصلية داخل `data/raw` لسه زي ما هي، ومتمسحش منها أي بيانات، ومبدأتش مرحلة التنظيف أو تعديل القيم.

## 5. الخطوة القادمة

الخطوة الجاية هتكون:

1. مراجعة العلاقات بين الجداول.
2. تحديد الـPrimary Keys والـForeign Keys.
3. التأكد من صحة العلاقات بين الملفات.
4. تحديد قواعد التنظيف المناسبة بناءً على المشاكل اللي ظهرت.
5. تنفيذ التنظيف على نسخة منفصلة من البيانات مع الحفاظ على الملفات الأصلية.

**الخلاصة:** خلصت الفحص الأولي للـ9 ملفات، وحددت أهم ملاحظات جودة البيانات، ووثقت النتائج. والخطوة التالية هي التحقق من العلاقات بين الجداول قبل البدء في التنظيف.
